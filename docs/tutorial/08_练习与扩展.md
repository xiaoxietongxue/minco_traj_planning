## 8.2 扩展 1：时间分配优化（L-BFGS）

### 动机

现在的时间分配是"梯形速度估计 + 一次整体缩放"（第 3 章 3.6 节）。整体缩放只能保证**最紧的那一处**刚好贴住限幅，其他段往往有很大余量。GCOPTER 的核心思想是：把每段时长 \(T_i\) 也作为优化变量，最小化

\[
J(T) = \underbrace{\int_0^{\sum T_i} \|p^{(3)}(t)\|^2 \,dt}_{\text{能量}} + \rho \sum_i T_i + \underbrace{\text{Penalty}(T)}_{\text{速度、加速度超限惩罚}}
\]

### MINCO 已经提供了梯度

这是 MINCO 最大的价值：能量对时间的梯度不需要数值差分，可以解析求出。GCOPTER 中的用法（`gcopter.hpp` 的 `costFunctional`）：

```cpp
minco.setParameters(points, times);
minco.getEnergy(cost);
minco.getEnergyPartialGradByCoeffs(partialGradByCoeffs);  // ∂E/∂c
minco.getEnergyPartialGradByTimes(partialGradByTimes);    // ∂E/∂T（系数固定时）

// 在这里把速度、加速度惩罚及其对 c、T 的偏导累加进去

minco.propogateGrad(partialGradByCoeffs, partialGradByTimes,
                    gradByPoints, gradByTimes);           // 链式法则：c 依赖于 T
cost += rho * times.sum();
gradByTimes.array() += rho;
```

`propogateGrad` 内部调用 `A.solveAdj` 求解伴随方程，代价与一次求解相同，是 \(O(N)\) 的。

### 保证 \(T_i > 0\)

L-BFGS 是无约束优化，GCOPTER 用一个光滑的双射把无约束变量 \(\tau \in \mathbb{R}\) 映射到 \(T > 0\)（`forwardT`）：

\[
T(\tau) = \begin{cases} \tfrac{1}{2}\tau^2 + \tau + 1, & \tau > 0 \\[4pt] \dfrac{1}{\tfrac{1}{2}\tau^2 - \tau + 1}, & \tau \le 0 \end{cases}
\]

对应的逆映射是 `backwardT`，梯度链式法则是 `backwardGradT`。

### 实现骨架

在 `minco_c_api.cpp` 中新增一个函数，例如 `minco_plan_opt`：

```cpp
#include "gcopter/lbfgs.hpp"

struct OptContext
{
    PlanInput in;              // 路径点和限幅
    double rho;                // 时间权重
    double weightV, weightA;   // 惩罚权重
};

static double costFunctional(void *ptr, const Eigen::VectorXd &tau, Eigen::VectorXd &gradTau)
{
    OptContext &ctx = *static_cast<OptContext *>(ptr);
    Eigen::VectorXd T;
    forwardT(tau, T);                               // 从 gcopter.hpp 复制过来
    double cost = 0.0;
    Eigen::VectorXd gradT = Eigen::VectorXd::Zero(T.size());
    for (int g = 0; g < ctx.in.dim; g += 3)         // 两组 3 维共享同一组时间
    {
        // 1. setConditions / setParameters
        // 2. getEnergy + 两个 PartialGrad
        // 3. 在每段上采样，累加超限惩罚及其偏导
        // 4. propogateGrad，把这一组的 gradByTimes 加到 gradT
    }
    cost += ctx.rho * T.sum();
    gradT.array() += ctx.rho;
    backwardGradT(tau, gradT, gradTau);
    return cost;
}

// 调用：
lbfgs::lbfgs_parameter_t param;
param.g_epsilon = 1e-6;
param.mem_size = 16;
Eigen::VectorXd tau;
backwardT(initialTimes, tau);                       // 用现有的启发式分配做初值
double minCost;
int ret = lbfgs::lbfgs_optimize(tau, minCost, &costFunctional, nullptr, nullptr, &ctx, param);
```

**关键点**：本项目把 6 维拆成两组 3 维求解（第 3 章），两组**共享同一组时间**，所以时间梯度要把两组的 `gradByTimes` **相加**。

### 验证方法

1. **梯度检查**：先不调用优化器，用有限差分对比 `gradTau`，相对误差应在 1e-6 以下。这一步最重要，梯度错了优化器也能"收敛"，只是结果不对
2. **对比**：优化前后的总时长、利用率峰值。理想情况下，优化后各段的利用率都接近 1
3. **调 \(\rho\)**：\(\rho\) 越大越"赶时间"，越小越平滑

惩罚项的写法可以参考 `gcopter.hpp` 中的 `attachPenaltyFunctional`：在每段上均匀采样，对超限量做光滑化（`smoothedL1`）后用梯形积分累加。

## 8.3 扩展 2：最小 snap（MINCO_S4NU）

GCOPTER 还提供 `MINCO_S4NU`（最小 snap，每段 7 次多项式，内部点 C6 连续）。无人机轨迹常用最小 snap，因为 snap 与电机转速变化率直接相关；机械臂一般用最小 jerk 就够了。

改造步骤：

1. 系数数组从 `c[piece][dim][6]` 改为 `[8]`
2. 首末条件从 `Matrix3d`（位置、速度、加速度）改为 `Matrix<double, 3, 4>`（再加上 jerk）
3. `evalPiece` 的 Horner 求值改为 7 次
4. 在 `minco_plan` 中增加一个 `order` 参数，或者新增一个函数

做完后对比两种轨迹的 jerk 曲线和能量，体会"最小化的阶数越高，曲线越光滑但越'懒'"。

## 8.4 扩展 3：替换为 ROKAE 真实机型

平台从一开始就把机器人相关的内容集中在 `robot_definition.m` 和配置文件中，替换步骤：

1. 从珞石官方获取 URDF 和网格文件（通常是一个 ROS 包，例如 `xxx_description/`），放到 `third_party/` 或 `robot/` 下
2. 修改 `config/platform_config.m`：

   ```matlab
   cfg.robot.source = "urdf";
   cfg.robot.urdfFile = fullfile(fileparts(mfilename("fullpath")), "..", "robot", "xxx_description", "urdf", "xxx.urdf");
   cfg.robot.eeName = "flange";          % 按 URDF 中实际的末端 link 名称
   ```

3. 运行 `startup_platform(RebuildVisual=true)`，重新生成可视化
4. 检查并调整：
   - `cfg.robot.vMax` / `aMax`：URDF 中的速度限值往往是电机极限，规划时应按手册打折
   - 关节路径点：零位定义不同，UR 的路径点在新机型上没有意义，需要重新设计
   - `cfg.cart.qInitDeg`：在第一个笛卡尔路径点附近找一个合适的初值
   - 奇异区：不同构型的奇异位置不同，用第 7 章的最小奇异值脚本重新检查

`robot_definition` 要求机器人必须是 6 轴。7 轴机型（如珞石 xMate 系列中的 7 轴型号）需要放宽这个检查，并把 `P.maxDim` 改为至少 7——MINCO 部分已经支持按 3 维分组求解任意维度，但 `MINCO_MAX_DIM` 宏也要相应改大。

## 8.5 扩展 4：ROS 2 / RViz

用 ROS Toolbox 把关节角发布到 ROS 2，就能在 RViz 里显示，也是对接真机控制器的第一步：

1. 顶层添加 ROS 2 `Publish` 模块，消息类型 `sensor_msgs/JointState`
2. 用 `Bus Assignment` 填写 `name`（关节名）、`position`（`q`）、`velocity`（`qd`）和时间戳
3. 在 ROS 2 中启动 `robot_state_publisher`，加载同一个 URDF
4. 在 RViz 中添加 `RobotModel` 显示

注意 Simulink 仿真默认跑得比实时快（或慢）。要让 RViz 中的动画与真实时间一致，需要启用仿真步调控制（Simulation Pacing）。

## 8.6 扩展 5：在线重规划

现在的路径点是 Constant 模块，仿真开始时规划一次。要支持运行中修改目标：

1. 把 `Waypoints` 从 Constant 改为输入端口（或从 ROS 话题订阅）
2. `minco_plan` 已经有输入缓存：输入不变时直接返回，输入变化时自动重新规划（第 4 章 4.6 节），这一层**不需要修改**
3. **需要修改的是首状态**：现在 `head` 只设置了位置，速度和加速度为 0。重规划时机械臂正在运动，必须把当前的 `pos`、`vel`、`acc` 作为新轨迹的首状态，否则速度会跳变。这需要给 `minco_plan` 增加 `headVel`、`headAcc` 参数，填入 `head` 矩阵的第 2、3 列
4. 重规划后 `minco_eval` 的时间要从 0 重新开始：用规划版本号的变化触发一个时间偏移

第 3 章证明的时间缩放等变性依赖于首末速度、加速度为 0，有了非零首状态之后整体缩放就不再精确成立。这也是 8.2 节时间优化值得做的另一个原因。
