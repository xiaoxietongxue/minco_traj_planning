# 第 7 章 仿真分析与调试

本章目标：学会从仿真数据中判断轨迹好坏，掌握"模型不报错但结果是错的"这类问题的排查方法。7.3 和 7.4 节是本项目开发过程中真实遇到的两个 bug 的完整复盘。

## 7.1 数据从哪里来

顶层的 5 个 To Workspace 模块把数据记录为 timeseries，`sim` 返回的 `out` 中可以直接取到：

| 变量 | 内容 | 尺寸（每个时刻） |
|---|---|---|
| `out.log_q` | 关节角 [rad] | 6 |
| `out.log_qd` | 关节速度 [rad/s] | 6 |
| `out.log_qdd` | 关节加速度 [rad/s²] | 6 |
| `out.log_eePos` | 末端位置（正运动学）[m] | 3 |
| `out.log_limitRatio` | [速度利用率; 加速度利用率; 越限标志] | 3 |

**取数据的坑**：timeseries 的 `Data` 维度取决于信号形状，可能是 `N×6`，也可能是 `6×1×N`。`plot_results` 中的 `toRows` 统一处理：

```matlab
function X = toRows(data, n)
X = squeeze(data);          % 去掉长度为 1 的维度
if size(X, 1) ~= n          % 保证每列是一个时刻
    X = X.';
end
end
```

自己写分析脚本时，第一步先 `size(out.log_q.Data)` 看一眼，可以省掉很多维度错误。

## 7.2 怎么判断一条轨迹"好不好"

`plot_results` 画出三张图，分别对应三个问题：

| 图 | 回答的问题 | 合格标准 |
|---|---|---|
| 关节轨迹（q / qd / qdd） | 是否平滑？是否超限？ | 曲线无跳变，qd、qdd 在红色虚线内 |
| 限幅利用率 | 时间分配是否合理？ | 峰值 < 1；速度峰值接近 \(1/\text{timeScale}\) 或加速度峰值接近 \(1/\text{timeScale}^2\)，说明时间没有浪费 |
| 末端路径 | 路径是否符合预期？ | 轨迹经过所有黄色路径点，没有奇怪的绕行 |

参考值（占位 UR5e、默认配置）：

| 模式 | 轨迹时长 | 速度利用率 | 加速度利用率 |
|---|---|---|---|
| 关节空间 | 5.5 s | 0.52 | 0.83 |
| 笛卡尔空间 | 13.5 s | 0.19 | 0.12 |

**为什么笛卡尔模式的利用率这么低？** 笛卡尔模式的时间分配是按**末端**线速度/角速度限幅（`cfg.cart.vMax`）缩放的，而利用率统计的是**关节**速度。0.25 m/s 的末端速度对 UR5e 来说很保守。这也说明一个重要事实：笛卡尔空间满足限幅 ≠ 关节空间满足限幅，两者都要检查。

除了看图，还要做**定量验证**。下面这段脚本验证两件事：正运动学是否正确、路径是否远离奇异。

```matlab
out = run_platform(PlanMode=2, Visualize=false, Plot=false);
robot = evalin("base", "platformRobot");
q  = squeeze(out.log_q.Data);     if size(q, 1) ~= 6,  q = q.';   end
ee = squeeze(out.log_eePos.Data); if size(ee, 1) ~= 3, ee = ee.'; end

errFK = 0; sv = zeros(1, size(q, 2));
for k = 1:size(q, 2)
    T = getTransform(robot.rbt, q(:, k).', robot.eeName);   % 离线再算一遍正运动学
    errFK = max(errFK, norm(T(1:3, 4) - ee(:, k)));
    J = geometricJacobian(robot.rbt, q(:, k).', robot.eeName);
    sv(k) = min(svd(J));                                     % 最小奇异值：离奇异多远
end
fprintf("正运动学最大误差 %.2e m，雅可比最小奇异值 %.3f\n", errFK, min(sv));
```

默认配置下输出：正运动学误差为 0，最小奇异值约 0.216。

这段脚本体现了一个调试原则：**用一条独立的计算路径交叉验证模型的输出**。Simulink 模型里用的是 Get Transform 模块，脚本里用的是 `getTransform` 函数，两者结果一致才说明模块配置正确。下面的第一个 bug 就是靠这种方法发现的。

## 7.3 Bug 复盘 1：正运动学方向设反

### 现象

笛卡尔模式第一次跑通后，检查路径点误差：记录下来的 `log_eePos` 在路径点处与目标位置相差约 **9.3 cm**。模型没有任何报错或警告。

### 排查过程

1. **先怀疑规划**：MINCO 在路径点处的插值误差在 1e-12 量级（第 3 章实验），规划没有问题
2. **再怀疑 IK**：用记录下来的 `q` 离线调用 `getTransform(robot.rbt, q, "tool0")`，得到的位置与路径点吻合，**IK 也没有问题**
3. **定位到正运动学模块**：同一个 `q`，离线计算正确而模型输出错误，问题只能出在 `ForwardKinematics`（Get Transform）上。检查参数，发现 `Source body = base_link`、`Target body = tool0`

### 根因

Get Transform 模块输出的是**把 Source 坐标系中的点变换到 Target 坐标系**的齐次变换，也就是"Source 在 Target 中的位姿"。要得到末端在基座中的位姿，应该是 `Source = tool0`、`Target = base_link`。设反后得到的是逆变换：

\[
T^{-1} = \begin{bmatrix} R^\top & -R^\top p \\ 0 & 1 \end{bmatrix}
\]

其平移部分是 \(-R^\top p\)，而不是 \(p\)，即"基座原点在末端坐标系中的位置"。

### 为什么不报错

逆变换也是一个合法的 4×4 齐次矩阵，维度、类型全都正确，Simulink 没有任何办法知道你"想要的是哪个方向"。**这类语义错误只能靠交叉验证发现。**

### 修复与预防

- 修复：`startup_platform` 中的 `configure_robot_blocks` 统一设置 `SourceBody = eeName`、`TargetBody = rbt.BaseName`，不再手动设置
- 预防：把 7.2 节的交叉验证脚本作为每次修改运动学相关模块后的回归检查

> **经验**：凡是涉及坐标变换的参数（from/to、source/target、parent/child），第一次使用时都要用一个已知结果的位形验证一次方向，例如零位时末端位置应该等于手册上的尺寸。

## 7.4 Bug 复盘 2：穿越肩部奇异

### 现象

修好正运动学后，笛卡尔模式的末端路径看起来正确，但限幅利用率图显示：

| 指标 | 数值 |
|---|---|
| 速度利用率峰值 | **8.42**（关节 1 速度 26.4 rad/s，限值 π rad/s） |
| 加速度利用率峰值 | **1657.7** |

而末端速度本身只有 0.25 m/s，非常平缓。

### 当时的路径点

```matlab
cfg.cart.waypoints = [
    0.45  0.13  0.35   -90  0  180
    0.45 -0.20  0.20   -60  0  180
    0.30 -0.30  0.45  -100  0  180
    0.25  0.30  0.30   -90  0  180
    0.45  0.13  0.35   -90  0  180
    ];
```

### 排查过程

1. **找到出问题的时刻**：速度利用率在 t ≈ 7.8 s 出现尖峰，对应第 3 → 4 个路径点之间
2. **看几何**：第 3 点 `(0.30, -0.30)` 到第 4 点 `(0.25, 0.30)` 横跨基座两侧。末端水平距离基座 z 轴最近只有 **0.133 m**
3. **算雅可比**：用 7.2 节的脚本计算最小奇异值，在 t ≈ 7.75 s 降到约 0——确认是奇异

### 根因

UR 构型的**肩部奇异**：当腕部接近关节 1 轴线附近的一个圆柱面时，关节 1 失去对末端水平横向运动的控制能力。要让末端在这个方向上保持哪怕很小的速度，关节 1 都需要极大的转速。

为什么路径点本身并不近，路径却靠近了？两个原因叠加：

1. 第 3、4 点的连线本身就从基座附近经过
2. **MINCO 曲线在急转处会向内侧弯**（最小 jerk 会"抄近路"），使实际路径比折线更靠近基座

还有一个有意思的细节：正好在奇异点 t = 7.75 s，关节 1 速度反而只有 0.16 rad/s，尖峰出现在奇异点**两侧**。这是第 5 章阻尼最小二乘的作用——在奇异点处主动放弃跟踪那个方向，但在接近奇异的区域，阻尼 \(\lambda = 10^{-3}\) 太小，挡不住速度暴涨。

### 修复

把路径点外移，并在横跨基座的两点之间增加一个过渡点（当前配置）：

```matlab
cfg.cart.waypoints = [
    0.45  0.13  0.35   -90  0  180
    0.50 -0.20  0.20   -60  0  180
    0.35 -0.35  0.45  -110  0  180
    0.50  0.00  0.40   -90  0  180   % 新增过渡点，把路径"撑"在外侧
    0.40  0.30  0.30   -90  0  180
    0.45  0.13  0.35   -90  0  180
    ];
```

修复后：

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 末端到基座 z 轴最小距离 | 0.133 m | 0.468 m |
| 雅可比最小奇异值 | ≈ 0 | 0.216 |
| 速度利用率峰值 | 8.42 | 0.19 |
| 加速度利用率峰值 | 1657.7 | 0.12 |

### 预防

- 笛卡尔路径点之间的连线不要横穿基座附近；大范围换向时加过渡点，或者干脆改用关节空间规划
- 每次修改路径点后检查速度利用率：**笛卡尔模式下利用率突然远大于 1，几乎总是奇异**
- 更彻底的方案见第 8 章：把奇异度作为约束加入 MINCO 优化

### 动手实验 7-1：复现这个 bug

把 `config/platform_config.m` 中的 `cfg.cart.waypoints` 改回上面"当时的路径点"，运行 `run_platform(PlanMode=2)`，在限幅利用率图中找到尖峰，再用 7.2 节的脚本画出 `sv` 随时间的曲线，确认两者的时间对应关系。做完记得改回去。

## 7.5 常见问题速查

| 现象 | 原因 | 解决方法 |
|---|---|---|
| 报错找不到 `Eigen/Dense` | Eigen 没装，或不在默认搜索路径 | `brew install eigen`；或设置环境变量 `setenv("EIGEN3_INCLUDE_DIR", "/your/path")`；或放到 `third_party/eigen`。搜索顺序见 `scripts/find_eigen.m` |
| 找不到 GCOPTER 头文件 | 子模块没拉下来 | `git submodule update --init` |
| 第一次仿真要等一两分钟 | 编译 C++ 自定义代码（含 Eigen 模板） | 正常现象，之后会快很多（约 25 s） |
| 改了 `minco_c_api.cpp`，仿真结果没变 | 自定义代码使用了缓存 | 关闭模型，删除 `slprj/` 和 `*.slxc`，重新运行 |
| `PlanFailedAssert` 断言失败 | `minco_plan` 返回负的错误码 | 看 `planStatus` 的值，对照第 4 章错误码表：常见的是 -3（路径点数超过 16 或少于 2）、-4（限幅不为正） |
| 改了 base workspace 里的 `P`，`run_platform` 没生效 | `run_platform` 会调用 `startup_platform` 重新生成 `P` | 改 `platform_config.m`；或者手动改 `P` 后直接 `sim("RobotTrajPlatform")` |
| `run_platform(PlanMode=2)` 时命令行提示"规划模式 关节空间" | 这条提示由 `startup_platform` 按配置文件打印，之后才切换模式 | 不影响结果，以 `PlanMode` 变量为准 |
| 在模型里找不到 `CartesianSpace` 子系统的内容 | 未激活的变体子系统不参与编译，部分工具看不到它 | 把 `PlanMode` 设为 2，再 `set_param(mdl, SimulationCommand="update")` |
| Mechanics Explorer 没弹出 | `Visualize=false`，或模型参数被关闭 | `run_platform(Visualize=true)` |
| 机器人在 Mechanics Explorer 中没有外形，只有坐标系 | 网格文件路径解析失败 | 看生成时的 `meshNotFound` 警告，检查 URDF 中的网格路径；然后 `startup_platform(RebuildVisual=true)` |
| 编译报路径相关的错误 | 项目路径含中文或空格，部分编译器不支持 | 本项目在 macOS + Clang 的中文路径下验证通过；其他平台出错时移到纯英文路径 |
| 笛卡尔模式的速度利用率远大于 1 | 路径经过奇异位形 | 见 7.4 节 |
| 末端路径与路径点对不上 | 正运动学方向设反，或 IK 收敛到另一组解 | 见 7.3 节；IK 问题检查 `cfg.cart.qInitDeg` |

## 7.6 本章小结

- 数据通过 To Workspace 记录，分析前先确认维度
- 从三张图（平滑性、限幅利用率、路径）判断轨迹质量
- 用独立的计算路径交叉验证模型输出，是发现语义错误的最有效方法
- 笛卡尔模式下利用率突然飙升，首先怀疑奇异
